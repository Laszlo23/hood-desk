# Hood Street Check-In Contract

On-chain check-in contract for Hood Street on Robinhood Chain (4663). Records one check-in per wallet per Vienna day.

## Contract Address

**NOT YET DEPLOYED**

Once deployed, the address will be added here and to the frontend `.env` file.

## Features

- One check-in per wallet per Vienna day (Europe/Vienna timezone)
- Emits `CheckIn` events for off-chain indexing
- No tokens, no payments, no admin control
- Transparent on-chain record

## Deployment

### 1. Deploy the Contract

```bash
# Make sure .env has PRIVATE_KEY set
source .env

# Deploy to Robinhood Chain
forge script script/DeployStreetCheckIn.s.sol:DeployStreetCheckIn \
  --rpc-url https://rpc.mainnet.chain.robinhood.com \
  --broadcast \
  --legacy
```

The `--legacy` flag is recommended for Robinhood Chain to avoid EIP-1559 issues.

**Save the deployed contract address from the output!**

### 2. Verify the Contract

Robinhood Chain uses Blockscout at https://robinhoodchain.blockscout.com

**Important:** Previous attempts to verify using `forge verify-contract` failed because Cloudflare blocks the Foundry user-agent. The recommended approach is manual verification via the Blockscout UI.

#### Manual Verification via Blockscout UI

1. Go to https://robinhoodchain.blockscout.com
2. Search for your deployed contract address
3. Click "Verify & Publish" or "Code" tab → "Verify and Publish"
4. Select verification method: **"Solidity (Single file)"** or **"Solidity (Standard JSON Input)"**

For **Single file** method:
- Compiler: `0.8.28`
- Optimization: **Enabled** with `200` runs
- Enter Solidity contract code: Copy from `src/StreetCheckIn.sol`
- Constructor arguments: None (the contract has no constructor parameters)

For **Standard JSON Input** method:
- Upload the `standard-input.json` generated by Foundry (found in `broadcast/` after deployment)
- Or use the compiler input JSON from `out/StreetCheckIn.sol/StreetCheckIn.json`

#### Alternative: Flatten and Verify

```bash
# Flatten the contract to a single file
forge flatten src/StreetCheckIn.sol > StreetCheckIn-flattened.sol

# Remove duplicate license identifiers if needed
# Then paste the flattened code into Blockscout UI
```

#### Troubleshooting Verification

If `forge verify-contract` is attempted and fails with Cloudflare errors:

```bash
# This will likely fail due to Cloudflare blocking Foundry
forge verify-contract <CONTRACT_ADDRESS> \
  src/StreetCheckIn.sol:StreetCheckIn \
  --verifier blockscout \
  --verifier-url https://robinhoodchain.blockscout.com/api
```

**Solution:** Use the Blockscout web UI instead (see above).

#### Verify Success

Once verified, the contract source will appear on the Blockscout explorer:
- https://robinhoodchain.blockscout.com/address/<CONTRACT_ADDRESS>
- The "Code" tab should show the verified Solidity source
- The "Read Contract" and "Write Contract" tabs will be available

### 3. Configure Frontend

After successful deployment and verification:

```bash
# Add to .env or .env.production in project root
echo "VITE_CHECKIN_CONTRACT=<DEPLOYED_ADDRESS>" >> .env.production
```

Example:
```
VITE_CHECKIN_CONTRACT=0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb4
```

Then rebuild the frontend:
```bash
npm run build
```

## Contract Interface

```solidity
// Check in (once per Vienna day)
function checkIn() external

// Check if an address can check in today
function canCheckIn(address wallet) external view returns (bool)

// Get current Vienna day number
function getCurrentDay() external view returns (uint256)

// Get last check-in day for an address
function getLastCheckInDay(address wallet) external view returns (uint256)
function lastCheckInDay(address) external view returns (uint256)

// Event emitted on check-in
event CheckIn(address indexed wallet, uint256 indexed day, uint256 timestamp)

// Error when trying to check in twice in same day
error AlreadyCheckedInToday()
```

## Vienna Day Calculation

The contract uses Vienna timezone (Europe/Vienna, UTC+1/UTC+2) for day boundaries:
- Day number = `(timestamp + 3600) / 86400`
- This uses UTC+1 as baseline (conservative boundary)
- Ensures check-ins align with the Vienna-based night ledger

## Integration

The frontend (`src/pages/Street.tsx`) automatically:
1. Detects if `VITE_CHECKIN_CONTRACT` is set
2. Sends on-chain transaction via wagmi/viem when configured
3. Falls back to off-chain check-in if no contract address
4. Updates the night ledger API after successful on-chain check-in
5. Shows transaction link on Blockscout
